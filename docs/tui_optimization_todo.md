# TUI 全面优化待办

状态：待推进。本文记录独立于主线的 TUI 优化队列，不代表以下能力已实现或问题已确认。优先推进[主线接续队列](plan.md#11-接续队列与提交粒度)；影响请求正确性、数据完整性或资源释放的问题仍随主线修复。

## 当前基础与范围

已有交流与状态页、流式 Markdown、工具活动、运行取消、ctx 精确地址编辑、声明 TOML 编辑、本地连接与界面偏好。优化基于这些能力逐项改进，不在界面中复制后端调度、插件装配或配置校验。

保持现有边界：接纳不等于运行完成；退出界面不取消 bot；断线不自动重发动作；ctx 写入不等于 TOML 保存；TOML 保存后重启生效。不得因显示优化改变公共 ID、运行身份或数据持久化规则。

## 优先级一：日常操作与反馈

- [ ] 梳理首次启动、连接失败、目标实例不存在、空白页与端点未开放的完整路径，给出可执行的下一步提示。
- [ ] 统一页面、编辑器、帮助及确认界面的键位与焦点规则；核对键盘、鼠标切换和退出后的焦点恢复。
- [ ] 优化状态列表的选择、滚动跟随、精确地址展示和筛选结果定位，长 ID 与 location 可完整查看。
- [ ] 明确草稿、未提交、提交中、已拒绝、结果未知和已完成的反馈；错误恢复时避免丢失未保存内容。
- [ ] 优化 JSON/TOML 编辑：行号、缩进、错误定位、撤销/重做、查找及长文本导航；先确认 OpenTUI 实际能力，再选择实现。
- [ ] 评估关闭编辑器和切换配置文件时的未保存提示、草稿保留与重新读取策略，避免把旧内容提交到新目标。
- [ ] 优化保存/删除确认的目标与差异展示；明确配置冲突后的核对流程，不把普通 ctx 读改写描述为事务。

验收：仅用键盘完成交流、查看工具、编辑与错误恢复；鼠标操作不改变确认目标；操作过程无焦点丢失、误提交或草稿被后台刷新覆盖。

## 优先级二：信息层级与布局

- [ ] 统一深灰背景、品牌蓝、间距、边框和文字层级，减少重复标签，保留必要的连接与运行反馈。
- [ ] 优化交流中的用户输入、模型过程输出、工具调用、结果和异常之间的视觉区分。
- [ ] 优化长运行和多轮输出的折叠、定位、查找与新内容提示，保留用户主动上翻的位置。
- [ ] 检查 Markdown 的表格、长代码、未闭合流式语法、链接及复制行为；不能因渲染改变原始内容。
- [ ] 完善窄/矮终端和运行中缩放布局，保证编辑内容、确认目标与主要动作可达。
- [ ] 检查中文、全角字符、emoji、组合字符和混合文本的宽度、光标、选择与换行。

验收：在宽屏、48×18 及更小窗口中检查真实内容帧，持续缩放不丢失输入；长文本可查看，主要动作不被裁切；颜色不是辨识状态的唯一手段。

## 优先级三：性能与长时间运行

- [ ] 量测长对话、大量工具活动、密集流式输出和大状态列表的帧耗时、CPU 与内存，再确定优化目标。
- [ ] 按测量结果评估增量更新、渲染节流和列表虚拟化，避免无依据地引入框架抽象。
- [ ] 检查多次切页、打开/关闭编辑器和帮助、重连及退出后的监听器、原生样式、任务与连接释放。
- [ ] 优化裁剪和长度限制的可见提示，保留重要关联信息，不把界面缓存当作完整审计存储。

验收：记录统一负载下的前后数据；长时间运行无持续内存增长或明显输入延迟；优化不削弱取消、重连和数据展示的一致性。

## 优先级四：偏好与终端兼容

- [ ] 评估在界面中设置连接、实例和显示偏好的入口，保留命令行临时覆盖与显式保存的区别。
- [ ] 评估多窗口偏好隔离、恢复默认值、坏文件修复和配置版本升级路径，不持久化凭证与请求身份。
- [ ] 完成 Windows Terminal/PowerShell 与其他受支持终端的人工操作验收，记录 Node FFI 与键盘协议限制。
- [ ] 核对普通 Escape、功能键、Ctrl 组合键、输入法、多行粘贴、无色模式和终端恢复。
- [ ] 完善启动帮助与快捷键发现方式；新增操作同步帮助、启动指南与验收用例。

验收：从干净配置启动，按文档完成主要操作；正常退出和失败退出都恢复终端；偏好不污染后端，多个界面可独立使用。

## 推进方式

- [ ] 开始优化前收集实际使用反馈与终端样例，区分已复现缺陷、体验改进和待评估方向。
- [ ] 每次选择一个可独立验收的切片，优先处理高频操作与已复现问题，不一次性重写整个 TUI。
- [ ] 复用控制器测试、OpenTUI 原生渲染测试和真实后端联调；视觉体验另补人工终端验收，不以假客户端测试替代。
- [ ] 完成一项后勾选对应待办，将变更与验收证据写入 [CHAGELOG.md](CHAGELOG.md)，同步 [启动指南](../examples/START.md)。
